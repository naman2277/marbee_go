# Phase 0 — Security hardening, Platform Console, production build

**Branch:** `claude/phase0-security` → `main` · 60 commits · merges cleanly (main has no new commits)
**Charter:** D-014 working model — CTO builds/tests/reviews; **CEO merges** and runs the deploy steps below.

## Why

Before the first customer (target: 10 Dec), Marbee had to stop being a demo with shared doors.
The Phase 0 audit (`docs/cpo/09-security-baseline.md`) found tenant data and secrets reachable
from the browser or by other tenants, and the production build was broken (1,102 type errors).
This PR closes every P0/High item and makes the app buildable.

## Risk
- **High-touch areas:** auth/workspace resolution (TD-20), RLS helpers (sql/91), every public edge function.
  All exercised on dev; attacker paths (no auth / anon key / other workspace) refused.
- **Behaviour changes users may notice:** admins can't set passwords (emails instead); webhook
  `basic`/`oauth2` modes now refused; API keys no longer accepted in webhook URLs; website push
  SDK "welcome" notification off until moved server-side (TD-21); auth emails need working SMTP.
- **Not exercised live:** HMAC/API-key webhook calls (unit-tested only), a real suspended/no-workspace
  account login (dev preview + DB tests only), a real pipeline run through the new worker.

## Deploy steps — staging / production (CEO, in this order)
**Dev is already done.** For a fresh project:
1. **SQL editor:** run `supabase/sql/01…93` in numeric order (skip `03_link_your_user`), then the
   `supabase/sql/v2/52…58` scale layer **after** 93 (v2/52 carries the suspension checks).
   Verify with `supabase/sql/tools/verify_91_suspension.sql` (all PASS).
2. **Secrets** (Edge Functions → Secrets): `MARBEE_SECRETS_KEY` (generate locally, keep a copy in the
   password manager — losing it makes sealed secrets unreadable), `APP_URL`, `CONSOLE_ORIGIN`,
   `FORM_CHALLENGE_SECRET`; AI keys only if Marbee-paid AI is offered (`OPENAI_API_KEY`).
3. **Auth settings:** disable public signups; set custom SMTP (SES) so invite/reset emails reach
   real customers; add `<APP_URL>/setup-password` to Redirect URLs.
4. **Edge functions:** deploy all 27 (24 existing + `ai-gateway`, `global-variables`, `platform-admin`;
   paste copies in `supabase/web-deploy/`). Use the JWT setting listed per function in
   `supabase/web-deploy/README.md`. Public endpoints called without a Supabase session must have
   JWT verification **OFF** — they authenticate callers themselves: `webhook-trigger`, `events-ingest`,
   `push-subscribe`, `push-engage`, `form-submit`, `chatbot-runtime`, `asset-gate`,
   `web-analytics-ingest`, `tenant-api`, `rtm-ingest`.
5. **Platform Console:** create the first platform admin (`sql/84` notes), deploy `apps/console`.
6. **Before go-live on dev data:** remove the `[TEST] Security test SEC-02 …` website and its events.
